# Научные компетенции МГТУ «СТАНКИН» в контексте мировой науки

Статический сайт о научных компетенциях университета на фоне мировой науки. Он показывает, в каких направлениях у университета выраженная специализация, как цитируются его работы по сравнению со средним мировым уровнем и какое место он занимает среди организаций России и мира. Все показатели рассчитываются автоматически по открытой базе научных публикаций [OpenAlex](https://openalex.org) (лицензия CC0).

**Адрес после публикации:** https://peretyaginmstu-jpg.github.io/stankin-science/

> Предварительная версия: страницы закрыты от поисковых систем (`noindex`, `robots.txt`). Индексацию включает `SITE.noindex = false` в `config/site.mjs`.

## Как считаются показатели

- **Индекс специализации** — доля направления в публикациях университета, делённая на долю этого направления в мировом потоке за тот же период. 1 — как в среднем по миру.
- **FWCI** (Field-Weighted Citation Impact) — цитируемость, нормализованная по подобласти, году и типу публикации; мир = 1,00. Показатель направления — среднее по работам.
- **Топ-10 %** — доля работ, входящих в 10 % самых цитируемых в своей области и году; мир = 10 %.
- **Доля в мировом потоке**, **рост** (второе пятилетие к первому — у университета и в мире), **место в России и мире** по числу публикаций.

Окно анализа — десять последних полных лет (сейчас 2016–2025), учитываются статьи, обзоры, главы книг и конференционные работы (`article`, `review`, `book-chapter`, `conference-paper`). Отозванные работы исключаются одинаково из местного и мирового периметров. Подробности и ограничения — на странице «Методика».

**Компетенции** — тематические группы классификации OpenAlex. Правила отнесения тем (по области, подобласти и ключевым словам в названии темы) лежат в `content/competencies.mjs`. Каждая тема попадает не больше чем в одну компетенцию; компетенция показывается на сайте, если у университета в ней не меньше 15 публикаций. Смешанные профильные кластеры Engineering Technology and Methodologies и Material Properties and Applications выделены отдельно: их нельзя автоматически приписывать целиком одной технологии. Группа ИИ и анализа данных включает и общие методы обработки данных и сигналов; попадание в неё не означает применения ИИ в каждой работе.

**Аудит аффилиаций.** В `config/site.mjs` опубликован список 188 идентификаторов работ с конфликтующей аффилиацией по аудиту от 02.10.2026. Выгрузка удаляет совпавшие ID до расчёта локальных показателей, соавторства и источников. На «Методике» показаны исходное, исключённое и оставшееся количества текущего снимка. Неоднозначные записи сохраняются. Нетипичная тема, включая Military Technology, сама по себе не является основанием удаления работы. Полные приватные материалы аудита в этот репозиторий не перенесены.

## Как обновляются данные

Сайт собирается и публикуется в GitHub Actions (`.github/workflows/pages.yml`):

1. `tools/fetch-openalex.mjs` выгружает данные из OpenAlex API в снимок `data/snapshot/snapshot.json`; число запросов и стоимость, сообщённая API, записываются в журнал;
2. `tools/build.mjs` рассчитывает показатели и собирает страницы в `dist/` (сеть не нужна);
3. `tools/check.mjs --publish` проверяет сборку и не пропускает демо-данные;
4. сборка публикуется на GitHub Pages, а снимок данных сохраняется в артефактах запуска на 90 дней.

Запуски: при каждом изменении `main`, по расписанию 3-го числа каждого месяца и вручную (Actions → «Публикация» → Run workflow; флажок `refresh` заставляет выгрузить данные заново). Обычная повторная сборка берёт последний снимок текущего месяца для той же конфигурации и не тратит запросы. Запуск по расписанию и `refresh` всегда обновляют данные и сохраняют новый снимок под отдельным ключом, чтобы следующая сборка не вернула предыдущую версию.

### Что нужно сделать один раз

1. **Доступ OpenAlex.** Workflow работает без ключа через разрешённый анонимный API. Опциональный бесплатный ключ увеличивает доступный суточный бюджет: получить его можно на https://openalex.org/settings/api и добавить в секрет `OPENALEX_API_KEY`.
2. **GitHub Pages.** Settings → Pages → Source: **GitHub Actions**.
3. Запустите workflow «Публикация» вручную или отправьте любое изменение в `main`.

Без ключа workflow выполняет ту же выгрузку и проверку. Для запросов с более чем 10 темами клиент выдерживает общий интервал 1,1 секунды, включая повторные попытки: API ограничивает такие запросы одним в секунду. Если API отказывает или лимит исчерпан, запуск завершается ошибкой и неполный снимок не публикуется. Текущие правила доступа: [официальная документация OpenAlex](https://help.openalex.org/api/authentication/).

## Локальная работа

Нужен Node.js 22 или новее. Зависимостей нет.

```bash
npm test                      # тесты: расчёты, графики, правила компетенций, сквозная выгрузка на имитации API
npm run demo                  # сборка из синтетических данных в dist-demo/ (на страницах — плашка «демо»)
node tools/serve.mjs --dir dist-demo   # просмотр: http://localhost:8080/stankin-science/
```

Сборка из настоящих данных:

```bash
node tools/fetch-openalex.mjs --no-key                   # → data/snapshot/snapshot.json
node tools/build.mjs                                     # → dist/
node tools/check.mjs --dir dist --publish
node tools/serve.mjs
```

При наличии ключа его можно передать в `OPENALEX_API_KEY` и запускать выгрузку без `--no-key`. Ключ не входит в снимок или журнал.

Если интернет доступен только через прокси, встроенный `fetch` в Node учитывает `HTTPS_PROXY` при `NODE_USE_ENV_PROXY=1` (Node 22.21 и новее).

Демо-снимок `data/fixture/snapshot.json` создаётся командой `npm run fixture` (`npm test` и `npm run demo` делают это сами). **Все числа, организации и публикации в нём выдуманы**: он нужен только для разработки и тестов, а публикацию такой сборки блокирует `tools/check.mjs --publish`.

| Что | Где |
|---|---|
| Состав компетенций, их названия и описания | `content/competencies.mjs` |
| Тексты страниц и подписи интерфейса (ru/en) | `content/i18n.mjs` |
| Русские названия областей и подобластей OpenAlex | `content/taxonomy.mjs` |
| Организация, окно анализа, типы публикаций, пороги, запрет индексации | `config/site.mjs` |

После выгрузки сборка печатает в журнал, сколько работ попало в каждую компетенцию и какие темы университета остались вне компетенций, — по этому списку удобно уточнять правила. Изменение правил компетенций меняет и мировой контекст (страны и организации), поэтому после правки нужна новая выгрузка; сборка из старого снимка скроет устаревший контекст и предупредит об этом на странице компетенции.

Если в OpenAlex найдутся дубли записи университета, журнал выгрузки и страница «Методика» их покажут; идентификаторы дублей добавляются в `INSTITUTION.extraIds`.

## Структура репозитория

На главной странице и в `/decisions/` доступна стратегическая инфографика: сильная публикационная база, изменение мировой доли направлений, потеря/рост доли СТАНКИН, матрица показателей и 11 выбранных промышленных тем. Фильтры сохраняют координаты и масштаб площади кругов. Карта связывает компетенции с замкнутым контуром «измерить → предсказать → скорректировать → подтвердить качество»; рубежи 2031/2036 обозначены как предлагаемые цели.

Расчёт воспроизводится в `src/lib/strategy.mjs`; параметры экспортированы как `STRATEGY_THRESHOLDS`, исходные значения и формулы опубликованы в `data/strategy.json`. Специализация для стратегической силы рассчитывается за 2021–2025, FWCI и размер круга — за 2016–2025. Рост мировой доли сравнивает два одинаковых пятилетия и нормируется на весь мировой поток тех же типов документов. Группы общего машиностроения/материаловедения исключены из отраслевого ранга; ИИ и моделирование отмечены как более широкие, чем производство.

`content/frontiers.mjs` содержит первичные научные источники и явно авторский синтез вектора; `content/topic-lenses.mjs` — выбранные темы OpenAlex. Ноль публикаций не доказывает отсутствие технологии. Эвристические действия и баллы не являются предписаниями бюджета, прогнозом рынка или подтверждением промышленной готовности.

### Материалы для совещания по ПИШ

`/pish/` и `/en/pish/` сопоставляют три темы с рекомендуемой гипотезой «Инженерия интеллектуальных станков и автономной точной обработки». Действующая ПИШ, рассматриваемая заявка ЦКП и новая обособленная школа имеют разные роли. Заказчик, главный конструктор и обязательства новой кооперации ещё не определены; существующее партнёрство не засчитывается как подписанное обязательство новой заявки.

`content/pish.mjs` хранит первичные источники, условия отбора 2026 года и минимальные значения приложения 10. `src/lib/pish.mjs` рассчитывает публикационную опору без конкурсного рейтинга. Каждая компетенция дополнена `cohorts.p1/p2`: число работ, средний и медианный FWCI, доля топ-10% и покрытие показателей. Диагностика чувствительности покрытий показывает среднее с темой T10626 и без неё; исходный массив и основные показатели не меняются. Это сравнение когорт, а не доказательство изменения качества работ.

Кнопка проектора увеличивает основные элементы, `Escape` возвращает обычный вид. Печать раскрывает дополнительные сведения и после завершения восстанавливает состояние страницы. SVG научной схемы и расчёты доступны в `data/pish-loop-ru.svg`, `data/pish-loop-en.svg`, `data/pish.json`. Числовые цели модели и промышленный эффект являются предложениями для испытаний; задержка модели и цикл ЧПУ показаны раздельно. Бюджеты из внутренних презентаций и полный текст заявки ЦКП в публичную сборку не включены.

## Проверка научных расчётов

Текущая сила в разделе «Решения» использует FWCI публикаций 2021–2025. Среднее за 2016–2025 сохранено как накопленный результат и не заменяет позднюю когорту. На странице ПИШ доступны детерминированные 95% bootstrap-интервалы среднего и разности когорт (2 000 повторов), интервалы Wilson для доли top 10%, медиана и влияние отдельных работ.

Численный аудит всех 20 групп выполняется при сборке и выгружается в `data/pish.json`. Проверка сборки останавливает публикацию, если контрольные суммы, знаменатели или показатели не сходятся. Подробный разбор: [docs/PISH_MATH_AUDIT.md](docs/PISH_MATH_AUDIT.md). Интервалы оценивают чувствительность к составу работ при условии независимости; они не доказывают качество исследований, готовность продукта или окупаемость.

## Безопасность и доступность

- Страницы статические, с Content-Security-Policy: скрипты, стили, шрифты и изображения загружаются только с самого сайта, встроенных скриптов и стилей нет.
- Адреса CSS и всей цепочки JS-модулей содержат общий хеш содержимого: новая страница получает совместимые ресурсы после публикации, даже если предыдущие версии сохранены в браузере.
- Подписи из данных OpenAlex экранируются при сборке и выводятся в подсказках через `textContent`.
- Цвета графиков проверены на различимость при нарушениях цветового зрения в светлой и тёмной теме; значения доступны в таблицах, подсказки открываются и с клавиатуры.

## Научные графики для выбора повестки

На `/pish/` и `/en/pish/` есть три интерактивные схемы: мировая динамика и недавний FWCI, дерево пяти семейств/15 вопросов и три пути от научного задела к предлагаемому исследованию. Схемы раскрывают источники и недостающие доказательства. Стрелки обозначают предложенные исследовательские связи, а не измеренное соавторство. Группы компетенций и основные темы OpenAlex показаны отдельно.

В разделе `#pish-explorer` Apache ECharts связывает координатную карту с исходными статьями. Можно отдельно исследовать 13 мировых тем или 20 групп, сравнивать мировую динамику с изменением доли СТАНКИН либо с FWCI выбранного пятилетия. Выбор точки обновляет показатели, годовое число работ СТАНКИН, публикации и ссылки на научные вопросы. Два мировых периода остаются фиксированными: смена пятилетия подробного просмотра не создаёт новую мировую временную серию.

`src/lib/explorer.mjs` строит независимый проверяемый экспорт `data/explorer.json` из того же снимка. Таблицы доступны без JavaScript. Официальный Apache ECharts 6.1.0 хранится локально с лицензиями и контрольными суммами; загружается только при приближении к разделу. CDN, внешние API и установка npm-пакетов для просмотра или сборки не нужны. Сохраняется строгая CSP; используется Canvas и текстовая подсказка `richText`.

Для публикации дополнительно строятся четыре рисунка на Python: все 20 групп и интервалы FWCI; мировая динамика 13 тем рядом с публикациями СТАНКИН; карта двух долей (мировая тема и СТАНКИН внутри неё); матрица 15 исследовательских вопросов. Каждый доступен по-русски и по-английски в SVG, PDF и PNG. На странице графики переключаются с клавиатуры, открываются в увеличении до 400% и сохраняют ссылки на отдельные рисунки. Без JavaScript и при печати доступны все четыре.

Для векторных рисунков выбраны [Matplotlib](https://github.com/matplotlib/matplotlib) и научные стили [SciencePlots](https://github.com/garrettj403/SciencePlots). Также рассмотрены [Plotly.py](https://github.com/plotly/plotly.py) и [Altair](https://github.com/vega/altair): для текущей задачи интерактивность обеспечивает сайт, а Python выпускает воспроизводимые SVG/PDF/PNG. Библиотеки установлены из PyPI в отдельной среде; Node-сборка и тесты остаются без зависимостей.

```sh
python3 -m venv .venv-plots
.venv-plots/bin/python -m pip install -r tools/requirements-plots.txt
PYTHON_PLOTS=1 node tools/build.mjs
.venv-plots/bin/python tools/test-scientific-plots.py
.venv-plots/bin/python tools/scientific-plots.py --data dist/data/pish.json --metrics dist/data/metrics.json --out dist/data/science-plots
node tools/check.mjs --dir dist --publish
```

GitHub Actions выполняет эти шаги после выгрузки/восстановления снимка. Генератор берёт числа из JSON сборки, не запрашивает сеть и не пересчитывает библиографию. `manifest.json` фиксирует исходные SHA-256, версии библиотек и суммы всех 24 файлов. Проверка запрещает публикацию старых рисунков с новыми данными. Обычный `npm run build` без `PYTHON_PLOTS=1` не включает ссылки на рисунки Python и не требует Python.

Рост мировой темы — изменение её доли среди всех мировых работ тех же годов и типов; изменение доли СТАНКИН внутри темы — другой показатель. Нулевая база даёт неизвестный рост. Публикации в широкой группе ИИ не доказывают наличие ИИ для станков, а условные bootstrap-интервалы не устанавливают научную новизну, готовность продукта или окупаемость. Подробности — `docs/PISH_MATH_AUDIT.md`.

### Мировые тренды и отраслевой индекс

`/trends/` и `/en/trends/` показывают 13 выбранных мировых тем на общей шкале с отдельным рядом работ СТАНКИН. Переключаются рост числа публикаций и изменение мировой доли; карточка темы раскрывает знаменатели, FWCI нового пятилетия, покрытие и переход к исходным статьям. Шесть научных переходов связывают широкие тренды с проверяемыми задачами и первичными источниками. Это не прогноз продаж и не автоматическая рекомендация финансирования.

`/industry-index/` и `/en/industry-index/` — предлагаемая методика индекса научного присутствия в станкоинструментальной тематике: работ университета на 10 000 мировых работ объявленного контура. Узкое ядро и расширение рассчитаны отдельно. Специализация, цитирование, top-10, интервалы и чувствительность к отдельным работам не объединяются в произвольный балл. Состав тем и работ доступен в интерфейсе и JSON; качество образования и промышленное внедрение не выводятся из публикаций.

Модули: `content/industry-scope.mjs`, `content/world-frontiers.mjs`, `src/lib/world-trends.mjs`, `src/lib/industry-index.mjs`. Выгрузки: `data/world-trends.json`, `data/industry-index.json`; обе страницы имеют скачиваемые SVG и статические таблицы без JavaScript. Первичные определения спорных кластеров проверены в официальном API OpenAlex. Ограничения и найденные включения непрофильных тем старого широкого классификатора описаны в `docs/PISH_MATH_AUDIT.md`.
